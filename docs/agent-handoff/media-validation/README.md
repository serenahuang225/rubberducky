# Media and device verification

The source contains browser speech recognition, optional recorded xAI hold-to-talk,
Claude photo/screenshot question intake, device capture controllers, and labeled simulated
fixtures. They are different capabilities; “all speech/perception is unavailable” is stale,
while “live voice works everywhere” would also be unsupported.

The hosted Claude demo supports own-question intake and has passed a text own-question
turn. xAI speech and LiveKit calling remain disabled. No actual iPad microphone/camera,
Pencil/palm, or background-device acceptance pass is recorded here.

Check each target's capability reporting, explicit permission/start/stop, text-only and
reduced-motion behavior, cancellation, late callbacks, and editable uncertain transcripts.
A countdown to a hint is a local display of server wait metadata, not a microphone feature
or a paid request on a timer. Raw ink must not become confidently graded handwriting.

Use current user instructions when arranging visible browser/device verification. Preserve
unrelated listeners and learner data. Old screenshots, fixture passes, and web build output
do not establish current visible or physical-device results.
